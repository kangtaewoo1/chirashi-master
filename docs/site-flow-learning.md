# 사이트별 가입·로그인·발행 지식

각 사이트의 정상 가입 절차를 어댑터로 구현하고, 관찰한 입력 항목과 실제 실행 결과를 구분해서 축적한다.

## 현재 연결된 텔판

- `telpan_adapter.FLOW`에 필수 입력 역할, 정상 가입·로그인·글쓰기 주소와 길이 제한을 저장한다.
- nickname은 로그인 계정 이름, password는 해당 계정 비밀번호, email은 본인 수신 이메일, snsId는 본인 텔레그램/카카오톡 연락처다.
- `signup_profile`과 `signup_once`는 이 정의를 실제 입력 해석과 가입 요청에 사용한다.
- 공통 `learn_signup_profile`은 텔판 전용 양식을 사용한다. 그누보드 등록 주소로 추측하지 않는다.
- 공통 `auto_signup`은 텔판 전용 처리로 분기한다. 이미 저장된 계정은 서버 로그인과 글쓰기 화면을 재확인하며, 계정정보가 없으면 필요한 역할을 기록하고 대기한다.
- 계정이 없다고 임의 gmail 주소나 SNS 아이디를 만들지 않는다.

## 저장과 검증

실행 서버의 `data/site_flow_knowledge.json`에는 값 없는 입력 정의, 주소, 학습 버전, 변경 이력, 단계별 실측 증거를 저장한다. 계정 비밀번호와 연락처는 넣지 않는다.

- 같은 정의는 버전을 재사용한다. 정의가 달라지면 버전을 올리고 이전 실측 증거를 이력으로 옮긴다.
- 가입 응답, 서버 로그인, 브라우저 발행, 서버 발행·공개 조회는 서로 다른 증거다.
- 가입·로그인 성공으로 발행 성공을 만들지 않는다. 브라우저 발행으로 서버 발행 검증을 대신하지 않는다.
- 서버 발행 증거에는 실제 글 주소와 비로그인 제목·본문 일치가 필요하다.
- 운영 사이트의 `/site-knowledge`에서 현재 학습 내용과 실측 상태를 확인한다.

## 다음 사이트를 추가할 때

Cozit은 `cozit_adapter`와 `/cozit` 화면을 통해 기존 소유자 프로젝트의
Timeline 개발 소식만 등록한다. 프로젝트 중복 생성이나 일반 광고 큐 발행은 하지 않는다.
이메일 로그인 정보는 서버 전용 암호화 파일에 저장한다. 제목 100·본문 600 UTF-16 단위를
넘으면 잘라서 보내지 않고 거절한다. 운영 한도는 `data/cozit_settings.json`에 별도로 저장하며,
기본 하루 1건·1440분 간격이다. `data/cozit_submission.json`에 제출 직전 기록을 남기고,
결과가 불명확하면 재제출을 차단한다. 공개 검증은 HTTP 200과 새 비로그인 브라우저의
동일 업데이트 카드 내 제목·본문 일치를 모두 요구한다. 새 프로젝트 URL을 만들지 않으므로
발행 영수증의 `content_kind=project_update`와 소식 제목·본문 해시로 기존 프로젝트 소개와 구분한다.

1. 공식 화면과 정상 제출 절차를 관찰하고 입력 역할·필수 조건·주소를 기록한다.
2. 해당 사이트의 어댑터를 공통 학습·가입·로그인·발행 분기에 연결한다.
3. 관리자 전용·인증·가입 횟수·발행 간격·TLS 제한을 유지한다. 거절 시 IP 변경이나 다른 제출 방식으로 재시도하지 않는다.
4. 결과가 불명확한 가입·글 제출은 중복 실행하지 않고 확인 대기로 남긴다.
5. 성공·거절·중복·연결 끊김·공개 조회 불일치를 테스트한다.
6. 실제 실행한 단계만 지식 저장소에 기록한다. 구현 완료, 모의 테스트 통과, 실제 서비스 성공을 구분한다.
