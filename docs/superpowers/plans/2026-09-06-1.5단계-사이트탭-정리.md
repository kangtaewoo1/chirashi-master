# 1.5단계: 사이트 탭 정리 — 발행가능만 표시 + 진행중 접이식 + 관리버튼 축소

> **For agentic workers:** py_compile 문법검사 + 라이브 확인으로 검증(테스트 없는 단일 Flask 파일). Steps use checkbox.

**Goal:** 사이트 목록을 "발행가능만" 기본 표시하고, 진행중은 접이식으로, 탈락은 영구제거하며, 사이트별 자동화 관리 버튼을 축소한다.

**Architecture:** `renderSites()`(JS)의 필터 로직과 `siteRow()`(JS)의 관리 메뉴를 수정. 백엔드 파이프라인·purge API는 이미 존재하므로 재사용.

## Global Constraints

- 수정 파일: `chirashi/app.py` 하나.
- 모든 커밋 전 `python -m py_compile chirashi/app.py` 통과.
- 커밋 끝에 `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`.
- 백엔드 발행/가입 로직 변경 금지 (UI/표시 필터만).
- 기존 `purgeDeadSites` / `/sites/purge` API 재사용 (이미 dry-run+확인+백업 구현됨).

## 현재 상태 (코드 확인 완료)

- `renderSites()` (6876~): 이미 `isDead`(rejected/failed/permission=false) 필터로 탈락은 숨김. "발행 불가 사이트도 보기" 토글 존재.
- `publishable` 판정 (6880): `permission && 관리자소스 && status≠rejected && write_test_status='passed' && verified_post_url이 http URL`.
- `purgeDeadSites()` (6896): 안 되는 사이트 dry-run 후 확인받고 영구삭제. 재사용.
- `siteRow()` (6855~6866): 관리 메뉴에 편집·가입올인원·가입폼재학습·발행드라이런·플랫폼감지·글쓰기학습·상태점검·발행테스트·삭제 9개 버튼.

## 현재와 목표의 차이

- **현재**: 탈락만 숨김. 진행중(가입준비 등)은 목록에 그대로 → "가입정보만 준비됨" 배지 노출.
- **목표**: 발행가능만 메인 표시. 진행중은 "진행중 N곳 보기" 접이식. 탈락은 제거.

- [ ] **Step 2: 3분류 필터로 교체**

현재 필터(showAll/isDead/shown/toggle) 블록을, 아래 3분류 로직으로 교체한다. `publishable` 판정은 6880줄과 동일 기준을 재사용(함수화).

```javascript
// 3분류: 발행가능 / 진행중 / 탈락
const srcOK=s=>['manual_admin','admin_bulk','legacy_admin','candidate_registered','verified_test'].indexOf(s.registration_source)>=0;
const isPub=s=>!!s.permission&&srcOK(s)&&s.status!=='rejected'&&s.write_test_status==='passed'&&/^https?:\/\//.test(s.verified_post_url||'');
const isDead=s=>(s.status==='rejected'||s.status==='failed'||(s.permission===false&&srcOK(s)&&s.write_test_status==='failed'));
const pubs=sites.filter(isPub);
const dead=sites.filter(s=>!isPub(s)&&isDead(s));
const prog=sites.filter(s=>!isPub(s)&&!isDead(s));  // 진행중: 발행가능도 탈락도 아닌 것
const showProg=window._siteShowProg||false;
const showDead=window._siteShowDead||false;
// 표시 대상 결정
let shown=pubs.slice();
if(showProg)shown=shown.concat(prog);
if(showDead)shown=shown.concat(dead);
const toggle=`<div class="row" style="margin-bottom:6px;font-size:11px;color:var(--d);flex-wrap:wrap;gap:8px">`
 +`<span style="color:var(--g)">🟢 발행가능 ${pubs.length}곳 표시 중</span>`
 +(prog.length?`<label style="display:flex;align-items:center;gap:4px"><input type="checkbox" style="width:auto" ${showProg?'checked':''} onclick="window._siteShowProg=this.checked;renderSites()">진행중 ${prog.length}곳 보기</label>`:'')
 +`<span style="flex:1"></span>`
 +(dead.length?`<label style="display:flex;align-items:center;gap:4px"><input type="checkbox" style="width:auto" ${showDead?'checked':''} onclick="window._siteShowDead=this.checked;renderSites()">안 되는 ${dead.length}곳 보기</label> <button class="btn btn-r btn-xs" onclick="purgeDeadSites()">🗑 안 되는 사이트 정리</button>`:'')
 +`</div>`;
```

그리고 이어지는 `if(!shown.length)` 및 테이블 렌더는 `shown` 변수를 그대로 사용하므로 유지. 단 빈 목록 메시지를 발행가능 기준으로 조정:

```javascript
if(!shown.length){$('siteList').innerHTML=toggle+'<p style="color:var(--d);padding:30px;text-align:center">발행가능 사이트가 아직 없습니다'+(prog.length?' (진행중 '+prog.length+'곳 — 위에서 보기)':'')+'</p>';return}
```
