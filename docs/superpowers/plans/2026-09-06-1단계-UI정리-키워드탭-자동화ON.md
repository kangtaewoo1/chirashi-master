# 1단계: UI 정리 + 키워드 탭 분리 + 자동화 항상 ON — 구현 계획

> **For agentic workers:** 이 계획은 표준 pytest TDD 대신, 이 프로젝트에 맞는 검증(py_compile 문법검사 + 배포 후 라이브 확인)을 씁니다. 이유: chirashi/app.py는 테스트가 없는 476KB 단일 Flask 파일이며 UI가 파이썬 문자열 내 HTML/JS입니다. Steps use checkbox (`- [ ]`) 구문.

**Goal:** 완전자동화가 항상 켜지도록 설정 기본값을 바꾸고, 발굴 탭의 수동 버튼을 제거하며, 키워드 작업실을 독립 탭으로 분리한다.

**Architecture:** 단일 파일 `chirashi/app.py`의 (1) config 기본값, (2) DASH_HTML 문자열 내 탭 네비게이션/패널/JS를 수정한다. 백엔드 파이프라인 로직은 이 단계에서 건드리지 않는다(2~5단계에서).

**Tech Stack:** Python 3 + Flask (단일 파일), 인라인 HTML/JS (Jinja 템플릿 문자열), git push → autodeploy(cron) 자동 반영.

**미해결 짚음 (확인 완료):** 상시발행 큐 편입 로직은 **현재 없다**. `worker_loop`(2985줄)은 `post_queue`를 소비만 하고, 큐를 채우는 것은 노래방/회원 스케줄·수동 발행뿐이다. 안전장치(`under_daily_limit`, `is_publishable`, `site_min_interval`)는 이미 존재. 따라서 **"발행가능 사이트에 24시간 자동으로 글을 큐잉하는 상시발행 루프"는 2단계에서 백엔드로 추가**한다. 1단계는 UI+설정 기본값까지만 (auto_pipeline은 발굴→검증→등록까지 자동화하고, 등록된 사이트에 상시발행하는 루프는 2단계). 이 경계를 지켜 1단계 범위를 UI/설정으로 한정한다.

**2단계로 이관되는 핵심 작업:** `publish_loop()` 신규 — 발행가능 사이트를 순회하며 `under_daily_limit`/`under_min_interval` 통과 사이트에 키워드 풀 기반 글을 `post_queue`에 넣는 상시 루프. `discover_loop`처럼 주기 실행. 이것이 있어야 "24시간 상시발행"이 완성된다.
