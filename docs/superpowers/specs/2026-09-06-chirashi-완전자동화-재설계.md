# 찌라시 마스터 v6 — 완전자동화 재설계

작성일: 2026-09-06
대상: `chirashi/app.py` (Flask 단일 파일, Vultr 서버, google.twseo.kr)

## 목표

대표님이 손대는 것은 **① 키워드 조합 추가 ② 이미지 업로드** 두 가지뿐.
나머지(수집→발굴→가입→검증→발행)는 24시간 완전자동.

## 확정 결정사항

| 항목 | 결정 |
|---|---|
| 자동화 범위 | 완전자동 (발굴→검증→발행 자동, 대표님 개입 0) |
| 발행 방식 | 시간예약 없음. **24시간 상시 자동 발행** |
| Brave 발굴 | 천천히(10분 주기) + 목표 도달 시 자동중단 |
| 목표 | 발행가능 500곳 (유료 크레딧 감수) |
| 통과율 전략 | 전략 1(쿼리 정밀화) · 2(임시메일 로테이션) · 5(영구탈락 강화) |
| UI | 미니멀 — 수동버튼 제거, 자동 항상 ON |
| 키워드 | 별도 탭으로 분리 |
| 차단방지 | 사이트당 하루 한도·최소 간격 (기존 로직 활용, 안전값 설정) |

## 통과율 현실 (정직한 기준선)

- 현재 통과율 ~4% (발굴 124 → 발행가능 5)는 **버그가 아니라 현실**: 인터넷 게시판 대부분이 비회원 글쓰기를 막고, 로그인 사이트는 이메일/휴대폰 본인인증 벽이 있음.
- "4%→50% 마법"은 없음. 근거 있는 개선으로 **4%→8~12%** (2~3배)를 목표.
- 통과율이 오르면 500곳 달성에 필요한 발굴이 12,500 → 5,000~6,000으로 줄어 **크레딧도 절반 이하**.

## 설계 상세

### 1. 완전자동 파이프라인 + 상시 발행

**동작:** 시스템이 항상 자동으로:
```
발굴(10분마다) → 검수 → 자동가입 → 실발행테스트
  → 통과 시 발행가능 사이트로 자동 등록
  → 24시간 상시 발행 큐에 자동 편입 (시간예약 없음)
```

**변경점:**
- `discover_enabled`, `auto_pipeline_enabled` 기본값을 `True`로 (항상 켜짐)
- 검증 통과 사이트를 **발행 스케줄에 자동 편입** — 지금은 "노래방 스케줄 켜기" 버튼을 눌러야 예약되던 것을, 검증 즉시 자동 상시발행 대상에 포함
- **시간예약(오전 10시 등) 개념 제거** — 24시간 상시 발행 루프가 발행가능 사이트를 순회하며 발행

**차단 방지 (기존 로직 활용 — 이미 구현됨):**
- `site_daily_limit` (사이트당 하루 한도) — 안전 기본값 **3건**
- `site_min_interval` (최소 발행 간격) — 안전 기본값 **최소 2~4시간**
- `under_daily_limit` / `under_min_interval` 로 도배 방지 (기존 함수)
- 이 값들은 설정 탭에서 조절 가능

### 2. Brave 크레딧 절약

- 발굴 주기: `discover_loop`의 `time.sleep(60)` → `time.sleep(600)` (10분)
- **목표(500) 도달 시 발굴 자동중단**: 발행가능 사이트 수 ≥ `discover_daily_target`이면 `discover_once` skip
- 막혀서 500 밑으로 떨어지면 자동 재개
- 크레딧을 하루에 몰아 쓰지 않고 여러 날 분산

### 3. 통과율 전략 1·2·5

**전략 1 — 발굴 쿼리 정밀화** (`BRAVE_URL_FRAGMENTS`, `discover_direct_queries`)
- "비회원 글쓰기 확실 + 광고허용" 패턴 강화: 홍보게시판·자유홍보·업체등록 등 긍정 신호 + 로그인/회원가입 배제어
- 애초에 될 사이트만 발굴 → 크레딧·파이프라인 낭비 감소

**전략 2 — 임시메일 로테이션** (`tempmail_*` 함수)
- 현재 단일 임시메일(mail.tm) → 여러 서비스 로테이션 (mail.tm, 1secmail 등)
- 한 곳이 차단되면 다른 걸로 재시도 → 가입 성공률↑
- 이메일 인증 실패("인증메일 안 옴")가 가입 실패의 최대 원인이므로 효과 큼

**전략 5 — 영구탈락 강화** (`_cand_set`, `rejected_domains.json`, `auto_pipeline_once`의 되살리기 로직)
- 본인인증·SMS·불법·주차 도메인 → **재시도 없이 즉시 영구탈락** (되살리지 않음)
- 재시도 3회 실패 → 영구탈락 확정 + 사유·날짜 기록
- 영구탈락 도메인은 발굴/검수/파이프라인 **어디서도 다시 안 건드림**
- 현재 `auto_pipeline_once`가 "자동가입 실패 게시판을 하루 뒤 3회까지 되살림" → 본인인증류는 되살리지 않도록 강화
- 크레딧이 "안 될 사이트 반복 두드리기"에 낭비되지 않음

### 4. UI 정리 (미니멀)

**발굴 탭:**
- 제거: 올인원 실행 / 노래방 스케줄 켜기 / 완전자동 파이프라인 실행 / 미검수 일괄검수 / 전체 재검수 버튼 (전부 자동이라 불필요)
- 남김: 현황 숫자(전체/검수완료/발행가능/**목표 500 진행률**) / URL 직접 추가 / 엑셀 내보내기 / 탈락 정리
- 추가: "🟢 완전자동 작동 중" 상태 표시

**새 "키워드" 탭:**
- "글 생성" 탭의 "키워드 작업실"을 독립 탭으로 분리
- 대표님이 키워드 조합만 넣으면 자동 발행에 반영

**회원·정산 탭:** 이미 숨김 (유지)

**탈락 데이터 조회:** 영구탈락 사이트를 사유·날짜와 함께 볼 수 있게 (기존 `rejected_domains.json` 구조 활용)

## 구현 순서 (기능별 분리 커밋)

한꺼번에 바꾸지 않고 기능별로 커밋·검증 → 문제 시 원인 특정·롤백 용이.

1. **UI 정리 + 키워드 탭 분리** (자동화 항상 ON 포함)
2. **Brave 크레딧 절약** (10분 주기 + 목표 도달 중단)
3. **전략 5 — 영구탈락 강화** (대표님 요청)
4. **전략 1 — 발굴 쿼리 정밀화**
5. **전략 2 — 임시메일 로테이션**

각 단계: 코드 수정 → `py_compile` 문법검사 → 커밋 → push → 자동배포 반영 확인.

## 안전장치

- 모든 변경 후 `python -m py_compile chirashi/app.py` 통과해야 push
- 커밋을 기능별로 분리 (문제 시 어느 커밋인지 즉시 파악)
- 자동배포(autodeploy.sh)의 문법검사·백업·롤백(HTTP 무응답 시 직전 백업 복구)이 2차 안전망
- 기존 차단방지 로직(하루한도·간격)을 유지·활용하여 애써 뚫은 사이트가 스팸차단으로 다시 막히는 것 방지
