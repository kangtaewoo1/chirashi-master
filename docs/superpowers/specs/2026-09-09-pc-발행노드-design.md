# PC 발행노드(가입·발행 오프로드) 설계

**작성일:** 2026-09-09
**요청(대표님):** "🤖 자동 가입·발행 대기 이거 pc로 작업 못하냐?" → 가입+발행까지 PC로(풀), PC는 강력·상시 켜둘 수 있음.

## 목표

서버(VPS)의 "🤖 자동 가입·발행 대기"(ready 후보) backlog를, 대표님 PC의 넉넉한 메모리로 크롬 여러 개 띄워 가입·발행하여 빠르게 소진한다. PC 발굴(pc_discovery.py)이 검색만 넘겼듯, 이번엔 가입·발행 실행을 넘긴다.

## 핵심 원칙

1. **코드 복제 금지 (방법 B):** PC는 별도 발행 스크립트를 새로 만들지 않는다. PC에 이미 있는 `app.py`의 엔진 함수(`generate_article`, `do_post`, `auto_signup_guarded`, `get_driver`, `_promote_candidate_to_site` 등)를 그대로 **import**해서 쓴다. 서버 엔진이 개선되면 PC도 최신(파일 동기화만).
2. **서버가 진실의 원천(source of truth):** 사이트 목록·후보·이력은 **서버에만** 기록. PC는 결과를 회신만 한다. PC 로컬 데이터 파일은 사용하지 않는다(노드 모드에서 읽기/쓰기 안 함).
3. **중복 방지:** 후보는 claim으로 원자적 잠금. 서버 `auto_pipeline_once`와 PC가 같은 후보를 처리하지 않는다.
4. **PC 장애 안전:** PC가 죽거나 멈춰도 claim은 만료되어 서버가 회수. 서버 단독 운영은 항상 그대로 동작(PC 꺼도 무방).

## 아키텍처

```
[대표님 PC]  pc_node.py                         [서버 VPS]  app.py
   │  1) POST /api/pipeline/claim {n, node_id}  ─────────▶  후보 N개를 claimed_by=node_id,
   │                                                        claim_expire=now+TTL 로 잠그고 반환
   │  ◀───────────────  후보 목록(가입·발행에 필요한 필드) ──┘
   │  2) app.py 엔진 import → 각 후보 가입·발행(로컬 크롬)
   │  3) POST /api/pipeline/report {node_id, results[]} ─▶  결과 반영:
   │                                                         - 성공: _promote_candidate_to_site(permission=True)
   │                                                                 + set_site_flag(mb_id/mb_pass)
   │                                                         - 실패: _cand_set(status=rejected/ready 재시도)
   │                                                         - claim 해제
   │  4) 반복(claim 없으면 대기)
```

## 서버 변경 (app.py)

### A. 후보 claim 필드
후보 dict에 3개 필드 추가(기존 구조 확장, 마이그레이션 불필요 — 없으면 미claim):
- `claimed_by`: 처리 중인 노드 id(문자열). 비어있으면 미claim.
- `claim_expire`: epoch초. 이 시각 지나면 만료(서버·다른 노드가 회수 가능).

### B. auto_pipeline_once 의 pend 필터에 claim 제외 (1줄 추가)
`pend=[c for c in cands if ... ]` 조건에 추가:
```python
and not _claim_active(c)   # PC가 잡고 있는(만료 전) 후보는 서버가 건드리지 않음
```
`_claim_active(c)`: `c.get('claimed_by') and float(c.get('claim_expire',0))>time.time()`

### C. POST /api/pipeline/claim  (before_request 토큰 allowlist 추가)
입력: `{node_id, n}`. 처리:
- `_cand_lock` 안에서 auto_pipeline_once와 **동일한 pend 선별 로직**으로 처리 가능 후보를 고르되, 미claim(또는 만료)인 것만.
- 상위 n개를 `claimed_by=node_id, claim_expire=now+TTL(기본 600초)`로 마킹, save_cands.
- 반환: 각 후보의 발행에 필요한 필드(id,url,domain,platform,bo_table,login_required,write_form,mb정보 힌트 등) + cfg 중 발행에 필요한 값(브랜드/전화/GPT키 등은 PC가 자기 config로 갖거나 서버가 내려줌 — 보안상 키는 내려주지 않고 PC 로컬 config 사용).

### D. POST /api/pipeline/report  (토큰 allowlist 추가)
입력: `{node_id, results:[{cand_id, ok, result_url, mb_id, mb_pass, bo_table, msg, is_temp}]}`. 처리(서버가 auto_pipeline_once의 성공/실패 처리와 **동일 로직** 재사용):
- ok+result_url: `_promote_candidate_to_site` + 필요시 `set_site_flag`. claim 해제.
- ok·URL없음 / 실패: `_cand_set`으로 rejected 또는 ready(일시실패 재시도). claim 해제.
- node_id 불일치 claim은 무시(늦게 온 회신 방지).

### E. claim 회수 루프
`auto_pipeline_once` 진입 시 만료 claim 자동 해제(별도 스레드 불필요, 기존 루프에 편승).

## PC 변경 (신규 pc_node.py)

- `pc_discovery.py`와 같은 위치(레포 안). app.py를 **같은 폴더에서 import**.
- 시작 시: 메모리 보고 → 안전한 동시 크롬 수 자동결정(app.py의 메모리가드 상수 재사용). 대표님 PC 강력하므로 기본 4~6.
- 루프: `claim(n=동시수)` → 각 후보를 스레드로 app.py의 발행/가입 함수 호출(auto_pipeline_once의 `_proc` 로직을 노드용으로 얇게 래핑) → 결과 모아 `report`.
- claim 0개면 30초 대기 후 재시도.
- 토큰·간격은 pc_discovery.py와 동일 방식(환경변수/기본값).
- Windows cp949 안전(stdout UTF-8 reconfigure, 이모지 print 회피).

## 보안

- claim/report는 **로그 토큰**(`log_token`)으로 인증(pc_discovery와 동일). before_request allowlist에 두 경로 추가.
- GPT/2captcha 등 **API 키는 서버가 PC로 내려주지 않는다.** PC는 자기 로컬 config(app.py가 읽는 config 파일)의 키를 쓴다 — 대표님 PC라 이미 동일 키 보유 가정. 키가 없으면 그 후보는 스킵하고 서버가 회수.
- 비밀번호·계정은 로그·응답에 노출 최소화(mb_pass는 report에서 서버 저장용으로만 전달, 로그 미표기).

## 비목표(YAGNI)

- PC 여러 대 동시 노드(멀티노드)는 지금 안 함(node_id로 확장 여지만 남김).
- PC 로컬 UI 없음(콘솔 로그만). 관제실에 "발행(PC)" 표시는 후속.
- 발굴(pc_discovery.py)과 통합 안 함 — 별도 프로세스로 병행 실행.

## 검증 기준

1. 서버 단독: PC 노드 미실행 시 기존과 100% 동일 동작(claim 없음 = auto_pipeline 그대로).
2. claim 원자성: 서버와 PC가 같은 후보를 동시에 처리하지 않음(claimed_by 잠금).
3. PC 강제종료: claim TTL(600초) 후 서버가 자동 회수해 재처리.
4. report 성공: PC가 발행 성공한 사이트가 서버 "발행가능"에 등록되고 이력에 남음.
5. 컴파일: `python -m py_compile app.py` + `node --check`(JS 무변경이지만 확인).
